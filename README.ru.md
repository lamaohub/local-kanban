# local-kanban

[![tests](https://github.com/lamaohub/local-kanban/actions/workflows/test.yml/badge.svg)](https://github.com/lamaohub/local-kanban/actions/workflows/test.yml)

Локальная канбан-доска для работы **в паре с Claude Code**: человек планирует и принимает задачи, Claude берёт их из очереди, делает и отчитывается — через токен-экономный CLI `kb`. Опционально зеркалит всё в GitHub (issues + Projects v2).

English version — [README.md](README.md).

![Доска](docs/screenshot-board.png)

![Дашборд](docs/screenshot-dashboard.png)

## Зачем

- **Очередь для Claude, а не просто доска.** Статусы повторяют реальный цикл: `бэклог → сделать → подготовка → делаю → деплою → проверяю → готово`. Claude берёт следующую задачу через `kb take`, работает и останавливается на «Проверяю» — принимает всегда человек.
- **Локально прежде всего.** Всё живёт в одном SQLite-файле на твоей машине. GitHub-синк опционален и выключен, пока не настроишь.
- **Честные метрики.** Время считается только пока Claude реально работает; дашборд показывает streak, цикл задачи и что ждёт тебя.

## Модель безопасности — прочитай сначала

Сервер слушает **только 127.0.0.1**, авторизации **нет**. Доска строго локальная: граница доверия — твоя машина. **Никогда не выставляй порт наружу** (никаких reverse proxy, `0.0.0.0`, проброса портов). Сторонние интеграции запускаются на той же машине и ходят на `127.0.0.1` (см. [docs/API.md](docs/API.md)).

## Требования

- **Node.js ≥ 22** (macOS или Linux) — у большинства стоит 24 LTS или новее
- Опционально, только для GitHub-синка: [`gh` CLI](https://cli.github.com/) с правом `project`:
  `gh auth login && gh auth refresh -s project`

## Установка

```bash
npm install -g local-kanban
local-kanban            # мастер настройки
local-kanban start      # доска на http://localhost:3100
```

Мастер спросит порт, папку данных, нужен ли GitHub-синк и куда поставить скиллы Claude Code — у каждого вопроса есть ответ по умолчанию, поэтому Enter-Enter-Enter достаточно. Он же создаст `ecosystem.config.cjs` для автозапуска через [pm2](https://pm2.keymetrics.io/).

У `local-kanban start` есть `--port <N>` и `--data <путь>`. Данные по умолчанию лежат в `~/.local-kanban`, вне каталога пакета, поэтому обновление пакета никогда не трогает доску.

Из исходников:

```bash
git clone <адрес-репозитория> local-kanban && cd local-kanban
npm install
npx local-kanban     # мастер настройки (необязательно)
npm start            # доска на http://localhost:3100
```

Команда `kb` глобально: `npm link` (или `npm install -g .`).

Первый запуск покажет пустой дашборд с предложением создать **демо-проект** — один клик создаёт, один удаляет.

### Настройку может довести сам Claude

На последнем шаге мастера первого запуска показывается готовый промпт (на языке доски). Вставь его
в Claude Code — он проверит, что работает `kb`, спросит, нужно ли зеркало в GitHub, заведёт первые
проекты с их путями и деплоем и покажет результат. Тот же промпт лежит в **Настройки → О доске**,
чтобы к нему можно было вернуться.

### Скиллы Claude Code

В `skills/` лежат два скилла:

- `skills/kanban` — учит Claude рабочему циклу задач (`kb take` → работа → `kb review`);
- `skills/deploy` — универсальный деплой от данных реестра проектов (`kb info`).

Установка — симлинк или копия:

```bash
ln -s "$(pwd)/skills/kanban" ~/.claude/skills/kanban
ln -s "$(pwd)/skills/deploy" ~/.claude/skills/deploy
```

## GitHub-синк (опционально)

Укажи owner и репозиторий для issues в **Настройки → Синхронизация** (или env `KB_GH_OWNER` / `KB_GH_REPO`). Без них доска работает в local-only режиме: без очереди и предупреждений. С ними каждая задача становится issue, а каждый проект получает GitHub Project `kb: <slug>` с теми же колонками. Синк односторонний (доска → GitHub), фоновый.

## Обновление

```bash
npm run update   # git pull + npm install + pm2 restart (если применимо)
```

Обновления не трогают данные: `data/` в .gitignore, миграции схемы прогоняются на старте автоматически — **со снапшотом до миграции** в `data/backups/pre-migrate/`.

**Откат:** останови сервер, восстанови свежий файл из `data/backups/` (суточные) или `data/backups/pre-migrate/` поверх `data/kanban.db`, затем `git checkout <предыдущий тег>` и запусти снова.

Релизы живут в `main` (стабильное, с тегами); ежедневная разработка — в `dev`.

## Переменные окружения

| Переменная | Дефолт | Смысл |
|---|---|---|
| `PORT` | `3100` | HTTP-порт (привязан к 127.0.0.1) |
| `KB_DATA_DIR` | `./data` | папка данных (SQLite, вложения, бэкапы) |
| `KB_LOCAL_ROOT` | `~/claude-projects` | корень локальных проектов-папок |
| `KB_URL` | `http://127.0.0.1:3100` | адрес доски для CLI `kb` |
| `KB_GH_OWNER` / `KB_GH_REPO` | — | цель GitHub-синка; пусто = синк выключен (можно задать и в Настройках) |
| `KB_PANEL_URL` | — | свой HTTP-источник статусов сервисов; пусто = локальный `pm2 jlist` |
| `KB_PANEL_INFO` | — | опциональный info.json внешней панели для синка категорий |
| `KB_SSE_MAX` | `20` | потолок одновременных SSE-соединений |
| `KB_SKILLS_EXTRA` | — | дополнительные корни скиллов через `:` |

Старые имена `PANEL_URL` и `PANEL_INFO` (без префикса) продолжают работать как запасные.

## Метрики и метка `noclaude`

Задачи, сделанные **руками** (без Claude), помечаются меткой `noclaude` — они считаются на дашборде отдельно и не подмешиваются в метрики Claude (время работы, цикл, доведено %), которые иначе исказились бы нулевым временем. Метка необязательна, можно ставить позже. Ручным задачам разрешён прямой переход в «Проверяю»/«Готово».

## Расширение

Полный HTTP API и SSE-поток событий — официальная точка расширения: боты, статистика и интеграции пишутся отдельными программами, без плагинов внутри страницы. См. [docs/API.md](docs/API.md).

## Язык интерфейса

Исходный язык интерфейса — английский, русский приходит переводом. Доска следует языку системы и переключается в **Настройки → Основные**; строка без перевода остаётся английской, а не утекает в чужую локаль.
